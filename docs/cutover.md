# Moving nectarnetwork.fun to Railway

**Prepared, not executed.** Nothing below changes until you say "go". Checked 2026-10-31 through the
Vercel and Railway connectors and Railway's current docs.

## What serves the domain today

- `nectarnetwork.fun` is a domain on the Vercel project **nectar-frontend** (Git: Nectar-Network/nectar).
- Its DNS is on Vercel's nameservers (`ns1.vercel-dns.com`, `ns2.vercel-dns.com`), so every record
  change below is made in Vercel → Domains → nectarnetwork.fun → DNS Records, not at a registrar.
- The nectar-frontend project also has `nectar.monster` (307 → nectarnetwork.fun), `nectarn.fun`
  (302 → nectarnetwork.fun) and the app subdomain on nectar.monster. `docs.nectar.monster` is on the separate
  Vercel project docs-site-nectar.
- The live site has no `robots.txt` or `sitemap.xml` (both 404).

Vercel's default records can't be deleted, but a record you add for the same name overrides them
(Vercel docs, Managing DNS records). That is what makes the switch, and the rollback, small.

## What Railway needs

From Railway's docs (Networking → Working with Domains):

- Each custom domain needs **two records**: a `CNAME` to a target such as `abc123.up.railway.app`,
  and a `TXT` record that proves ownership. Without the TXT record the domain returns 404 even once
  the CNAME resolves.
- At the apex, Railway supports **CNAME flattening or a dynamic ALIAS** record. Vercel DNS supports
  `ALIAS` (it is one of its record types: A, AAAA, ALIAS, CAA, CNAME, MX, SRV, TXT), so the apex works
  without moving nameservers.
- Railway issues a Let's Encrypt certificate (ECDSA, 90 days, renewed at 30 days left), usually
  within an hour of DNS resolving. The zone's CAA records already allow `letsencrypt.org`.
- The Hobby plan allows 2 custom domains per service: the apex and `www`.

The exact CNAME target and TXT name and value are generated by Railway when the domain is added to
the service (step 2 below), so they are not written here yet. Adding them was blocked from this
session as a domain change, by design.

## Records to add (at "go")

| Name | Type | Value | Replaces |
| --- | --- | --- | --- |
| `@` | ALIAS | the CNAME target Railway shows for `nectarnetwork.fun` (e.g. `xxxxxx.up.railway.app`) | Vercel's default `@` ALIAS |
| `www` | CNAME | the CNAME target Railway shows for `www.nectarnetwork.fun` | the `*` wildcard, for `www` only |
| as shown | TXT | the ownership record Railway shows for `nectarnetwork.fun` | nothing (new) |
| as shown | TXT | the ownership record Railway shows for `www.nectarnetwork.fun` | nothing (new) |

Leave MX, SPF, DKIM, CAA and the Google verification TXT exactly as they are. Leave the `*` wildcard
in place (it keeps other subdomains on Vercel).

## Steps

1. **Before "go".**
   - Production variables on the Railway `web` service in **nectar-network**: `IP_HASH_SALT`,
     `RESEND_API_KEY`, `PILOT_FROM`, `CRON_SECRET` (you set these; `DATABASE_URL`,
     `PILOT_NOTIFY_TO` and `PORT` are already set).
   - Connect the production `web` and `indexnow` services to Nectarlabs-io/landing (branch
     `claude/design-implementation-hmz7s5`), then **Disable** autodeploy on both, and deploy the
     commit you want with **Deploy Latest Commit**.
   - Check it on `https://web-production-2de65.up.railway.app`: `/`, `/contact` (submit the form;
     the row appears in the production Postgres and the email arrives), `/api/health`,
     `/media-kit`, `/features` → 301.
2. **Add the custom domains in Railway.** Production `web` → Settings → Public Networking →
   `+ Custom Domain` → `nectarnetwork.fun` (target port 3000), then again for
   `www.nectarnetwork.fun`. Copy the CNAME target and the TXT record shown for each.
3. **Add the four records in Vercel DNS** from the table above. The two TXT records are harmless on
   their own; the `@` ALIAS is the moment traffic moves.
4. **Wait for Railway to verify** both domains (green check) and issue certificates.
5. **Check DNS and TLS** from any machine:

   ```bash
   dig +short nectarnetwork.fun
   dig +short www.nectarnetwork.fun CNAME
   ```

   ```bash
   curl -svI https://nectarnetwork.fun/ 2>&1 | grep -iE "^< HTTP|subject:|issuer:|expire date:|x-robots-tag"
   ```

   Expect `HTTP/2 200`, an issuer of Let's Encrypt, a future expiry date, and **no** `X-Robots-Tag`.

   ```bash
   curl -sI https://www.nectarnetwork.fun/contact | grep -iE "^HTTP|location"
   curl -sI http://nectarnetwork.fun/ | grep -iE "^HTTP|location"
   curl -sI https://nectarnetwork.fun/features | grep -iE "^HTTP|location"
   curl -s https://nectarnetwork.fun/robots.txt | head -5
   curl -s https://nectarnetwork.fun/sitemap.xml | head -5
   curl -s https://nectarnetwork.fun/cb936410115550f57a308d52475044dd.txt
   curl -sI https://nectarnetwork.fun/media-kit/svg/nectar-mark.svg | grep -i "^HTTP"
   ```

   Expect: www → `301` to `https://nectarnetwork.fun/contact`; http → `301` to https;
   `/features` → `301`; robots.txt and sitemap.xml load; the key file prints the key; the media-kit
   file returns `200`.
6. **Check the other domains still redirect** (they are served by Vercel and send visitors to the
   name `nectarnetwork.fun`, which now resolves to Railway):

   ```bash
   curl -sI https://nectar.monster/ | grep -iE "^HTTP|location"
   curl -sI https://nectarn.fun/ | grep -iE "^HTTP|location"
   curl -sI https://docs.nectar.monster/ | grep -iE "^HTTP"
   ```

   Expect `307` and `302` to `https://nectarnetwork.fun/`, and `200` for the docs. Keep
   `nectarnetwork.fun` attached to nectar-frontend in Vercel: those two redirects are configured
   against it, and keeping it there makes the rollback a two-record change. (Optional, later: make
   both redirects permanent, 308 or 301, so search engines consolidate on nectarnetwork.fun.)
7. **Turn on IndexNow:** set `INDEXNOW_ENABLED=true` on the production `web` service. The `indexnow`
   cron service runs daily at 06:17 UTC and records only what IndexNow accepts.
8. **Search engines:**
   - Google Search Console: the domain already has a `google-site-verification` TXT record, so the
     Domain property may already be verified. Submit `https://nectarnetwork.fun/sitemap.xml` and
     re-inspect `/` with URL Inspection to request a recrawl.
   - Bing Webmaster Tools: verify the domain (or import from Search Console) and submit the sitemap.

## Rollback

1. In Vercel DNS, delete the `@` ALIAS and `www` CNAME you added. Vercel's default records take over
   again and `nectarnetwork.fun` is served by nectar-frontend, whose last production deployment is
   untouched. (Records here have a 60 s TTL for Vercel's defaults; allow a few minutes for caches.)
2. Optionally delete the two Railway TXT records and remove the custom domains from the Railway
   service.
3. Check with `curl -sI https://nectarnetwork.fun/` that the response comes from Vercel
   (`server: Vercel`).

Nothing in this site changes the nectar-frontend or docs-site-nectar projects, and the nectar-landing
Vercel project is left as it is until the cutover is done.
